11/// Creates a [`Scene`] using BSN (Bevy Scene Notation) syntax. These docs primarily show syntax.
12///
13/// See [`bevy_scene`] module-level docs for in-depth details about usage and behavior.
14///
15/// ## Syntax Reference
16///
17/// The syntax consists of scene entries which are listed below, which all act on the scene in some way.
18/// Often, this is by inserting/patching a component or its values or including other scenes.
19/// Scene entries can have prefix characters which specify/disambiguate the following entry.
20///
21/// ```rust,ignore
22/// bsn! {
23///     <scene entry>
24///     :<cached scene include>
25///     #<name>
26///     @<SceneComponent>
27///     ~<custom Template>
28/// }
29/// ```
30///
31/// ### Scene entries
32/// | Examples                                   | Explanation                                                                                                    |
33/// | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
34/// | `CompA`                                    | A unit or default component. Fields, if any exist, will be default                                             |
35/// | `CompA(val)`<br>`CompA(val, val)`          | Tuple Component with some fields specified. Unspecified fields will be default, see [patching]                 |
36/// | `CompA { name: val }`                      | Component with some fields specified. Unspecified fields will be default, see [patching]                       |
37/// | `mymodule::CompA { name: val }`            | Same as above, but referring to the component by module path                                                   |
38/// | `CompA { name }`                           | Component with Rust's "field assignment shorthand". Evaluates to `CompA { name: name.into() }`                 |
39/// | `MyEnum::Variant`                          | Enum Component `MyEnum` with the `Variant` variant                                                             |
40/// | `template_value(component)`                | Insert the component value from a variable `component`                                                         |
41/// | `template_value(CompA::from_str("foo"))`   | Insert the component value by immediately calling the constructor                                              |
42/// | `template(|context| { ... })`              | Register a function/closure returning a Template (eg. Component). Its passed [`context`] allowing World access |
43/// | `~MyType`<br>`~MyType {name: var}`         | Type implementing [`Template`], the prefix is used to distinguish it from Components which use [`FromTemplate`]|
44/// | **Including Scenes**                       |                                                                                                                |
45/// | `scene()`<br>`scene(val)`                  | Include the result of a `impl `[`Scene`] function                                                              |
46/// | `{ expr }`                                 | Include the result of `expr`, which should be a [`Scene`]                                                      |
47/// | `@MySceneComp`                             | Include a [`SceneComponent`]. Fields, if any exist, will be default                                            |
48/// | `@MySceneComp { @prop: val }`              | Include a [`SceneComponent`] with a `prop` field, passed to this components scene function                     |
49/// | `@MySceneComp { name: val }`               | Include a [`SceneComponent`] with a normal field, works the same as it does for normal components              |
50/// | `@MySceneComp { @prop: val1, name: val2 }` | Include a [`SceneComponent`] with both a `prop` and a field                                                    |
51/// | `:"scene.bsn"`                             | <div class="warning">Asset format not yet implemented!</div> Include a cached scene asset file                 |
52/// | `:scene()`<br>`:@MySceneComp`              | <div class="warning">Caching for scene includes not yet implemented!</div> Include a cached scene function     |
53/// | **Named entity references**                |                                                                                                                |
54/// | `#MyName`                                  | Becomes `Name("MyName")` when used as a `part` of a scene                                                      |
55/// | `CompA(#MyName)`<br>`scene(#MyName)`       | Referring to the entity which was named `MyName` in this scope, results in an [`EntityTemplate`] being passed  |
56/// | `Name("Foo")`                              | Manually sets the Name component, can be put after a `#MyName` to use a custom name while allowing references  |
57/// | **Observers**                              |                                                                                                                |
58/// | `on(\|ev: On<Ev>\| { … })`                 | Attaches an entity [`observer`] for the [`EntityEvent`] `Ev` to this entity. In this example, using a closure  |
59/// | `on(my_observer)`                          | Attaches an entity [`observer`] for the [`EntityEvent`] `Ev` to this entity. In this example, using a function |
60/// | **Relationships**                          |                                                                                                                |
61/// | `Children []`                              | Spawns each entry as a child of this entity, see **Scene Lists** below for details                             |
62/// | `ChildOf(entity)`                          | Makes **this** entity a child of `entity`, accepts an [`Entity`] or a `#Name` reference ([`EntityTemplate`])   |
63/// | `MyRel []`                                 | Like [`Children`], but uses any [`RelationshipTarget`] component                                               |
64///
65/// ### Scene Lists
66///
67/// Scene list syntax appears in Relationships and the [`bsn_list!`] macro, surrounded by `[ ]`.
68///
69/// Unlike parts of a scene, which are whitespace-separated, the scenes in a scene list are comma-separated.
70/// Each comma-separated single-entity scene uses the same syntax as a single [`bsn!`] macro call.
71///
72/// Note: The examples below omit the relationship or macro call, `Children [<scene list>]` or `bsn_list![<scene list>]`
73///
74/// | Example                      | Meaning                                                                                                               |
75/// | ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
76/// | `[ #Child1 CompA, #Child2 ]`     | Spawns 2 children, one with `(Name("Child1"), CompA::default())` and the other with `Name("Child2")`              |
77/// | `[ (#Child1 CompA), (#Child2) ]` | Same as above, with explicit parentheses                                                                          |
78/// | `[ #First, { expr }, #Last ]`   | Spawns an entity with name `First`, then every entity from the [`SceneList`] returned by expr, then one named `Last` |
79/// | `[ #First, ({ expr }), #Last ]` | Same as above, but the `expr` should result in a [`Scene`] and will only spawn one entity using it                   |
80///  
81/// ### Values
82///
83/// Values in BSN (as in `val`,`val1` etc used above) are generally any literal Rust values, plus a few bsn-specific quirks.
84///
85///
86/// | Example                          | Meaning       | Explanation                                                                             |
87/// | -------------------------------- | ------------- | --------------------------------------------------------------------------------------- |
88/// | `1`                              | Unsigned int  | Positive number, common types: [`usize`], [`u8`], [`u32`], [`u64`]                      |
89/// | `1` or `-1`                      | Signed int    | Positive or negative number, common types: [`i32`], [`i64`]                              |
90/// | `1.1` or `-0.1` or `1.` or `-2.` | Float         | Floating point number, common types: [`f32`], [`f64`]                                   |
91/// | `true` or `false`                | Bool          | Boolean, type: [`bool`]                                                                 |
92/// | `"somename"`                     | String        | Text, types: [`String`] or [`&'static str`](str)                                        |
93/// | `"mypicture.png"`                | Asset path    | Asset, when used in a field which expects a [`Handle`] to the matching [`Asset`] type     |
94/// | `some_function(1)`               | Function call | Calls a function with the provided arguments                                            |
95/// | `GREEN`                          | Constant      | Fixed value, must be in scope                                                           |
96/// | `std::f32::consts::PI`           | Constant      | Fixed value, uses full path so doesn't need to be in scope                              |
97/// | **Expression syntax**            |               |                                                                                         |
98/// | `{ 1 + 2 }`                      | Expression    | Any rust expression works in `{}`, in this case addition of 2 integers                  |
99/// | `{ vec![true, false] }`          | Vector        | An expression returning a [`Vec`], a collection of multiple items of one specific type. |
100/// | `{ bsn!{ Text("foo") Style } }`  | Scene         | Sometimes, you may need to pass a small [`Scene`] as a value to something else            |
101///
102/// ### Other Rust syntax
103///
104/// If you're new to Rust, you might struggle with some of its syntax when you see it in or around BSN.
105/// Here are some syntax snippets which haven't been shown so far:
106///
107/// | Syntax            | Meaning       | Explanation                                                     |
108/// | ----------------- | ------------- | --------------------------------------------------------------- |
109/// | `\|param\| { … }` | Closure       | A closure; effectively an unnamed function                      |
110/// | `Vec<T>`          | Generic type  | A type with a generic type parameter `T`                        |
111/// | `//`              | Comment       | Line comment; all text after `//` on the same line is ignored   |
112/// | `/* */`           | Block comment | Standard Rust block comment; all text inside `/* */` is ignored |
113/// | `bsn! { … }`      | Macro call    | Calls a macro on the value inside of the braces                 |
114///
115/// ### Syntax example
116///
117/// Example macro showcasing most syntax (complex, most scenes won't look like this):
118/// ```rust,ignore
119/// bsn! {
120///     some_scene()        // include a scene function
121///     #SomeName           // entity name, will insert Name("SomeName")
122///     ComponentA          // component without a value will use default
123///     ComponentB(0.0)     // passing a value, other fields will use default
124///     Node {
125///         height: px(0.1) // same with named fields, unmentioned ones stay default
126///     }
127///     on(|evt: On<MyEntityEvent>, mut query: Query<&mut ComponentB>| {  // add an observer
128///         let mut b = query.get_mut(evt.entity).unwrap();
129///         b.0 += evt.value;
130///     })
131///     Children [                   // spawning multiple related entities using a RelationshipTarget component
132///         #Child1 ComponentA       // whitespace doesn't have to be newlines
133///         ,                        // entities are comma-separated
134///         (other_scene() #Child3), // parentheses around a single entity are optional
135///         Link(#SomeName),         // passing a entity reference to a component as `Entity`, component has to implement FromTemplate
136///         @MySceneComponent {      // components which derive SceneComponent have scenes and can be inherited from
137///             @some_prop: 3,       // props, look like fields prefixed with @ but end up passed to the components scene as arguments
138///             normal_field: 5      // while normal fields are the actual fields of the component
139///         },
140///         Node {
141///             width: some_var      // you can directly use variables without {}
142///         }
143///         ComponentB({some_var + 3.})  // values can be expressions, when wrapped in {}
144///         @Container {
145///             @items: {
146///                 bsn_list![                // sometimes you may need to nest macro calls
147///                     #item1 SomeComponent, // note: the name #item1 here is in its own scope
148///                     some_scene() #item2
149///                 ]
150///             }
151///         }
152///     ]
153/// };
154/// ```
155///

157/// [`context`]: https://docs.rs/bevy/latest/bevy/ecs/template/struct.TemplateContext.html
158/// [`EntityTemplate`]: https://docs.rs/bevy/latest/bevy/ecs/template/enum.EntityTemplate.html

164/// [patching]: https://docs.rs/bevy/latest/bevy/scene/index.html#patching

180/// Creates a [`SceneList`] using BSN (Bevy Scene Notation) syntax.
181///
182/// This is useful when you want multiple root entities in your scene
183/// that do not share a common parent, or if you want to create multiple scenes at once.
184///
185/// Like in relationships in [`bsn!`], commas separate entities,
186/// while whitespace separates components on the same entity.
187///
188/// All root entries in a [`bsn_list!`] share a single name scope, so sibling root entities
189/// can cross-reference each other by `#Name`.
190/// This is not possible with separate [`bsn!`] calls, and is a key motivation for using [`bsn_list!`].
191///
192/// See [`bsn!`] for an example of the syntax.
193/// See the [`bevy_scene`] crate docs for a high-level overview of the key concepts.
194///
195/// [`SceneList`]: https://docs.rs/bevy/latest/bevy/prelude/trait.SceneList.html
196/// [`bevy_scene`]: https://docs.rs/bevy/latest/bevy/scene/index.html
197#[proc_macro]
198pub fn bsn_list(input: TokenStream) -> TokenStream {
199    crate::_bsn::bsn_list(input)
200}

202#[proc_macro_derive(
203    SceneComponent,
204    attributes(component, require, relationship, relationship_target, entities, scene)
205)]
206pub fn derive_scene_component(input: TokenStream) -> TokenStream {
207    let mut ast = parse_macro_input!(input as DeriveInput);
208    TokenStream::from(scene_component::derive_scene_component(&mut ast))
